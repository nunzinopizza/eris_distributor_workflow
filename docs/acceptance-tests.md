# Acceptance Tests

## Test convention

Each test is pass/fail. “Pass” means every stated expected result is observable in the configured solution and its records. Tests that depend on an open decision are blocked until that decision is controlled in the specification.

| ID | Specification reference | Setup / action | Pass criteria |
| --- | --- | --- | --- |
| AT-01 | §3 steps 1–3; §4; TR-003–TR-005 | Start an intake with missing required source information, save it, then complete and create the order. | Incomplete record remains a resumable draft; no Internal Order ID is created until completion; created order receives one permanent ID. |
| AT-02 | §3 steps 4–5; §4; §9; TR-005, TR-011 | Create an order using an inactive contact, an unstored recipient, a free-form product, a fractional quantity, and duplicate product selection. | Each prohibited selection is blocked; duplicate line can only be combined or canceled; accepted line uses a stored active contact, approved product, and whole quantity. |
| AT-03 | §8; §9.2–§9.3; TR-010–TR-011 | Create two same-day orders and then change a master price after an order line is saved. | Order IDs and document suffixes are unique under the stated rules; saved order-line price does not change; pallet estimate rounds up and excludes non-pallet items. |
| AT-04 | §10; TR-012 | Exercise each of the four entry points using valid test data. | Each path creates or links the intended order without duplicate records; copy/revise excludes dates, document numbers, approvals, emails, adjustments, payments, documents, and pickup status. |
| AT-05 | §11; §13; §23; TR-013 | Generate PO, BOL, and invoice test documents with 18 order lines. | Each is a readable, exactly one-page, 8.5 x 11 portrait PDF with required coordinated branding/content; current file and prior version history are available. |
| AT-06 | §12; §15–§16; TR-014, TR-017–TR-018 | Prepare a suggested-PO approval package. | Package contains only the suggested PO attachment and displays exact PDF, stored recipients, required subject, full body, attachments, and stated logistics summary; approval decision is logged. |
| AT-07 | §16; TR-018 | Reject and return an approval, then reassign and resubmit it. | Reject/return require comments; reassignment is limited to eligible approvers and logged; resubmission remains in the same approval history. |
| AT-08 | §5; §15; TR-006, TR-017 | Attempt to attach a non-PDF and a PDF category blocked from sending; attempt a free-form recipient. | Non-PDF and blocked PDF cannot be included, blocked category has no override, and free-form recipient cannot be used. |
| AT-09 | §3 steps 14–18; §13; TR-015 | Generate and print a BOL, confirm it, revise it, and attempt final workflow without reconfirming print. | Print alone does not confirm; revision keeps number/filename, shows REVISED/revision, retains prior version, requires reprint; final send remains blocked until Confirm Printed. |
| AT-10 | §3 steps 18–23; §4; §13; TR-015 | Finalize a BOL whose quantities differ from the approved suggested PO. | Final PO is regenerated from finalized BOL quantities; final PO approval is required; BOL remains printable but combined sending is disabled until approval and print blockers clear. |
| AT-11 | §4; §13; TR-015 | Clear all final send blockers and send the PO/BOL package; separately force a send failure. | Success marks both documents Sent using logged exact attachments; failure marks neither Sent and preserves the package for retry. |
| AT-12 | §17; TR-019 | Supply one strong confirmation match and one ambiguous confirmation email with a difference. | Strong match links to order; ambiguous item is queued for review and not guessed; difference creates Confirmation Issue and does not overwrite order values. |
| AT-13 | §17; TR-019 | Run the no-response process through the third unanswered follow-up. | First reminder occurs next business day; later reminders follow the stated daily schedule; third unanswered follow-up stops automation and sets human-intervention status. |
| AT-14 | §14; TR-016 | Mark an order Picked Up after correcting its actual pickup value. | Scheduled and corrected actual values are retained/logged; invoice draft is generated from confirmed BOL quantities and approved final PO prices. |
| AT-15 | §14; §16; TR-016, TR-018 | Add each invoice adjustment type, including Other without and with a description; submit invoice approval. | Other without description is blocked; all adjustments are separate lines and require approval; approval package shows exact PDF, recipients, subject, complete body, and attachments. |
| AT-16 | §14; TR-016 | Approve an invoice package and inspect the sent message. | Approval warning is shown before decision; approval immediately sends the exact reviewed package; email contains required ACH content, Net 15 terms, security reminder, and stated subject. |
| AT-17 | §14; §25; TR-016, TR-027 | Calculate an invoice due date on a weekend and on a recognized holiday. | Weekend result moves to Friday; holiday handling is tested only against the approved calendar selected under OD-14. |
| AT-18 | §18; TR-020 | Process a strong remittance match and a mismatched remittance. | Strong match creates Payment Notice with extracted settlement data but does not mark Paid; mismatch remains Review Required; only user Confirm Payment changes settlement status. |
| AT-19 | §18; TR-020 | Apply credit memos across one or more settlements, including an amount above remaining balance. | Available balance and statuses update correctly; overuse and double use are blocked; one settlement can include payment and multiple credit memos. |
| AT-20 | §18; TR-020 | Confirm payment, generate the final packet, attempt close without review, then close after review. | Confirmed payment moves to Ready for Closeout; packet includes required documents and only user-marked material correspondence; Close Order occurs only after user action and is logged. |
| AT-21 | §3 step 34; §4; §17; TR-004, TR-019 | Cancel an order and attempt to reopen it; process a declined order. | Cancellation is recorded immediately and cannot reopen; declined-order behavior is available only as approved under the controlled distinction in OD-25. |
| AT-22 | §5.3–§5.4; §21; TR-007, TR-023 | Review one completed workflow’s history, versions, statuses, approval decisions, sends, and payment actions. | Records reconstruct users, timestamps, values, versions, stages, and material actions; older documents remain recoverable. |
| AT-23 | §22–§23; TR-024–TR-025 | Attempt restricted actions with an ordinary user and inspect production records. | Unauthorized access is denied; required ownership, connection, notification, support, and readiness records are populated before release. |

## Deferred-decision gate tests

The following must be added or unblocked only after their corresponding decision is controlled: suggested-PO post-approval send (OD-06), pickup-time approval reset (OD-03), approval reminders (OD-01), exact matching threshold (OD-22), message-category rules (OD-08), invoice post-approval changes/send failure (OD-11–OD-12), and retry/lock/timeout behavior (OD-04, OD-13).
